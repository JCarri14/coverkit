# Publish CoverKit on GitHub Pages and as a shadcn registry

## Before your first push

1. Unzip into a new public repository, ideally named `coverkit`.
2. Run `corepack enable`, `corepack prepare pnpm@10.20.0 --activate`, `pnpm install`.
3. **Commit `pnpm-lock.yaml`** generated by that install, for deterministic CI builds.
4. Run `pnpm registry:sync` and `pnpm check`. Review all failures before publishing.
5. Confirm that `registry.json` and the README point to `https://github.com/JCarri14/coverkit` (already configured).
6. Run `pnpm registry:check` and commit the checked-in `registry/` files.

## GitHub Pages

1. Go to **Settings → Pages → Build and deployment → Source → GitHub Actions**.
2. Push to `main` or manually run **Deploy GitHub Pages** (`.github/workflows/pages.yml`).
3. The workflow computes `VITE_BASE_PATH`, `COVERKIT_SITE_URL` and `COVERKIT_GITHUB_REPO` from the repository name and builds the static site.
4. Verify these pages after deployment:
   - `https://jcarri14.github.io/coverkit/` (English redirect)
   - `https://jcarri14.github.io/coverkit/en/` and `/es/`
   - `https://jcarri14.github.io/coverkit/en/gallery/` and `/es/gallery/`
   - `https://jcarri14.github.io/coverkit/en/docs/` and `/es/docs/`
   - `https://jcarri14.github.io/coverkit/en/components/media-card/` and `/es/components/media-card/`
5. Inspect page source: each route should include HTML content, a unique title/description, canonical URL and JSON-LD.

For a `JCarri14.github.io` root repo, the workflow uses base `/`. For a custom domain, adjust the workflow environment settings accordingly.

## shadcn GitHub registry

Once the public GitHub repo contains a correct `registry.json`, developers can install the component from another configured shadcn project:

```sh
pnpm dlx shadcn@latest add JCarri14/coverkit/media-card
```

For optional animation, use `pnpm dlx shadcn@latest add JCarri14/coverkit/animated-media-card`. This item includes the base source and installs `motion` and `lucide-react`; the ordinary `media-card` item requires only `lucide-react`. No private CoverKit package is required.

**Required smoke test before announcing the command:** create a clean React consumer with shadcn's `components.json`; run that command and compile the consumer. This cannot be verified until the repository is published.

## SEO and previews

- Real SSR-prerendered HTML is emitted from Vite's SSR bundle by `scripts/prerender.mjs`, then hydrated client-side.
- Generated files include eight localized routes under `/en/` and `/es/`, a root English redirect, `sitemap.xml`, reciprocal `hreflang`, and OG image metadata.
- SEO metadata is configured via `COVERKIT_SITE_URL` and `COVERKIT_GITHUB_REPO` during the Pages build.

See [SEO.md](SEO.md) for verification and limitations.

Official docs: https://ui.shadcn.com/docs/registry/github and https://vite.dev/guide/static-deploy.html
